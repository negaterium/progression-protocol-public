# Skill audit matrix

This matrix is the review ledger for all 38 shared skill modules. `Matrix`
means the module is positioned in the visible tree. `Reserve` means it is
shown in the unpositioned system archive. The runtime column describes what the
current branch actually executes; a name or flavor line does not count as a
mechanic until a server path and regression test exist.

Every skill surface now exposes a runtime-contract label:

- **Active Effect** means the server action and generated summary resolve an active ability.
- **Passive Effect** means a registered passive modifier is consumed by an existing game path.
- **Stat Imprint** means the module contributes its documented level/rank-scaled `stat_bonus`,
  with no separate combat, recovery or control trigger.
- **Lore Only** is reserved for future catalog entries that have flavor text but no current
  runtime contract.

The catalog description is still shown as the module's lore and reference text. Generated
summaries and the runtime label are the authoritative explanation of what the current branch
actually applies.

### Decision record for the remaining stat-imprint modules

The following modules were reviewed against the current action, combat,
regeneration, status, quest and shadow contracts. Their flavor suggests a
future specialization, but the engine has no matching event boundary that can
resolve those claims without inventing a new rule. They therefore remain
deliberate stat imprints for this phase; the generated UI label makes that
boundary visible to players.

| Module | Decision | Current contract |
| --- | --- | --- |
| Deep Work, Algorithm, Coding, System Design | Retain as Intelligence imprints | Character-level Intelligence imprint only. |
| Time Blocking, Sense | Retain as Perception imprints | Character-level Perception imprint only. |
| Flow State | Retain as an Intelligence imprint | Character-level Intelligence imprint only. |
| Endurance | Retain as a Vitality imprint | Character-level Vitality imprint only. |
| Bear Form | Retain as Strength and Vitality imprints | Character-level Strength and Vitality imprints only; no transformation, spell lockout or damage-reduction trigger is registered. |

## Next mechanic slices

The remaining lore modules should be promoted one family at a time, with a
formula, a trigger surface, a generated display summary and a focused test.
The completed slices establish the order and evidence standard:

1. **Survival:** Iron Body and Mana Shield use existing boss-turn contracts,
   Iron Will uses the boss status-application boundary, and Iron Skin uses the
   shared defense calculation; Longevity uses the shared Max HP formula.
2. **Offense:** Dagger Mastery, Iron Fist, Shadow Step, Fireball, Curse of Agony, Quicksilver
   and Bloodlust use existing unarmed, boss-evasion, magic-damage, current-HP
   pressure, second-strike and physical-damage profiles;
   the remaining recovery/control modules need a new event path or a deliberate
   existing-contract mapping.
3. **Recovery and control:** Meditation uses the existing regeneration contract,
   Focus uses the existing quest mana-cost contract, Life Drain uses the existing boss-round HP update with a bounded heal, Taunt
   uses the existing defense calculation, Holy Light uses the existing
   direct-healing paths, and Purification uses a quest-start saving throw against
   ordinary status effects. Entangling Roots uses the existing boss-turn
   boundary to skip one non-cosmic counter-attack when its saving throw succeeds.
4. **Monarch systems:** Domain of the Monarch uses the existing shadow-army
   damage path for assigned and passive attacks; storage and shadow ownership
   remain unchanged.

No item in these groups should be described as an active spell, transformation,
damage-over-time effect, or crowd-control effect until its server-side trigger
exists. This keeps the System's dramatic voice aligned with what the game can
actually resolve.
